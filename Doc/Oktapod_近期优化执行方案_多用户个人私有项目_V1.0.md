## 1. 执行目标与边界

### 已确认的实施合同（2026-09-07）

当前服务面向内部可信用户，项目、对话、任务和成果按用户私有。组织 `owner/member` 只决定公共配置管理能力；维护者没有读取其他用户私有项目的额外权限。团队协作暂不实施。

- 会话：Personal 的普通 HTTP 禁止代签，包括维护者；撤销使用组织、本人用户与会话 ID 三重约束，他人和不存在的会话均为 404。远程请求缺失 Principal 时失败，本地装配保留显式可信入口。
- 公共配置：Bootstrap 返回 `permissions.manage_instance`。新安装第一个密码账户在注册事务内成为 owner，后续账户为 member；旧库不猜测维护者，由部署者执行 `oktapod user set-owner --username <name>`，仅提升已有活跃登录账户并产生审计。
- 账号生命周期：工作区单独持有 QueryClient 和 SSE 管理器；401 卸载工作区、取消请求、关闭事件源并弃置缓存；登录完成整页导航。SSE 网络错误先复查会话，不能把断网等同退出。按用户存储的草稿和偏好保留。
- 发送：Composer 控制器保存原文、附件引用和请求快照，失败后可重试或恢复至空输入框，允许继续输入。调用方生成稳定请求键；两种 Turn 传输使用同一幂等命名空间，受理回放优先于当前任务状态判断。24 小时后仅允许恢复草稿。
- 调度：首次任务也写入 `conversation_message_queue`；空闲会话立即尝试领取，同会话忙时保持持久排队。迁移 069 支持空前置任务和递增领取版本。领取和 Task 创建均检查会话责任，取得资格后才采集 Workspace、项目指令与 Git 基线。旧直接 Task API 在同会话忙时返回 409。
- 暂停、审批、输入、blocked/unknown 保持责任；取消后仍等待执行退出与未决 Receipt 处理。旧领取者不能创建 Run 或释放新领取。纯 Ask 不占项目写资格，Steering 保留现有检查点语义。

主要实现入口为 `application/turn_admission.go`、`application/project_queue.go`、SQLite 的 `project_task_creation.go` / `project_queue.go` / `turn_admission.go`、前端 `authentication-lifetime.tsx` 与 `composer-send-controller.ts`。后续 Codex 应从验收矩阵未关闭项继续，不能重复重写已实现合同。

升级前暂停受理、正常停止旧服务并备份 DataRoot，禁止新旧调度器同时运行。迁移不删除历史记录；降级 SQL 明确失败，回滚必须使用升级前备份。历史多任务责任不确定时须人工处理，不自动取消或重放。

完成一个可靠的多用户个人 Agent 产品：不同用户各自使用私有项目；用户能够在对话中描述目标、执行、审批、查看成果并从失败中恢复。

**只安排五项当前修复：身份签发、公共配置权限、前端账号生命周期、发送失败恢复、同项目任务竞争。** 契约整理随相关修复完成，签名发布在准备发行时单独收口。

| 保留 | 不进入当前实施 |
|---|---|
| Go + React、模块化单体、SQLite、Windows/Linux 原生交付 | 微服务、分布式数据库/队列、PostgreSQL 全面适配 |
| 现有 Principal/Scope、owner/member 基础 | 团队协作、SSO、企业 RBAC、邀请/共享/任务接手 |
| AgentTurnAssembler、ToolRuntime、Durable Harness、Receipt/Checkpoint | 重写 Agent Loop、第二事件源、动态内核插件体系 |
| Work/Code、Skill/MCP、现有文档 Runtime | 为扩充能力列表新建工具市场、多 Agent 或后台自治平台 |
| 会话级执行排队/共享文件冲突提示 | 自动 worktree 创建、合并、回收的完整子系统 |

不按文件行数安排重构，不引入没有具体调用方收益的接口，不恢复没有实际性能问题支撑的基准项目。未来需求只能登记，不能加入当前批次。

本方案不承诺固定工期。每项先写能捕获原问题的最小回归，再提交一个可独立评审的实现批次。若证据表明某静态风险已有有效保护，记录调用链和回归结果后关闭该发现，不为完成任务卡强行重写。

## 3. 不可破坏的合同

1. HTTP 使用真实 Session Principal；普通 HTTP 不得回退到默认本地用户。CLI/bootstrap 的可信入口单独处理。
2. 私有项目 Owner 限制同时覆盖读、写、下载、预览、事件流、资源引用；禁止只在列表页过滤。
3. 现有 Run 快照、InputHash、Authorization、Receipt、Checkpoint、Lease/Fencing、Artifact Evidence 和完成门禁保持可恢复。
4. `unknown` 副作用不得自动重试；Steering 在已提交检查点之后生效；Task 终态来自持久化事实。
5. `session_entries.entry_seq` 与 `messages.server_seq` 不合并；持久 SSE cursor 与临时 `run_live` 不混用。
6. 生成 API 代码通过生成流程更新；不手改生成物，不改变旧迁移，不清空数据来修复兼容问题。
7. Secret 继续通过数据库加密 SecretStore；日志、测试输出、截图、文档不得保存真实凭据。
8. 所有验收使用临时 DataRoot、独立端口、动态测试凭据和隔离文件；不得真的删除用户项目。
9. 默认不 commit/push/tag/deploy；用户后续明确授权时，完成相应门禁再执行。

## 4. OPT-01：关闭 Personal 会话身份绕过

**目标：** 普通已登录用户不能以另一个用户身份进入私有项目。

**先读：** `Src/internal/adapters/httpapi/server.go:78–106,233–300,891–932`；`Src/internal/application/service.go:245–300`；`Src/internal/application/security.go`；`Src/internal/adapters/db/sqlite/store.go:284` 起；`Src/internal/adapters/db/sqlite/password_auth.go`；`Src/tests/integration/user_auth_test.go`。

**允许改动：** 上述身份/会话用例及其 Repository 端口、相关 HTTP/OpenAPI、相邻测试。新增文件应放在已有目录。只有原数据结构无法表达会话 Owner 校验时才加最小迁移；当前优先用已有 user_id。

**实施要求：**

- 在隔离实例注册 A/B，以 A 的合法会话及 CSRF 调用管理式签发/撤销接口，写出当前失败的负向回归。
- Personal 普通 HTTP 不提供代签会话能力；密码登录/注册的内部创建会话继续正常工作。可信本地入口显式区分，不让业务服务凭借“调用者未传 Principal”自动降级为管理员。
- 撤销会话同时校验组织和所属用户，正常注销只影响自身。Application 用例承担授权，HTTP 做映射，Repository 做带身份条件的写入。
- 检查正式路由和可信测试 Handler 两种装配，防止只在测试路径加保护。

**必须验收：**

1. A 指定 B 的 user_id 签发会话被拒绝，无 B 的新 session；A 撤销 B session 被拒绝，B 原会话仍有效。
2. A/B 登录、注销、自有项目创建/查询正常；跨用户 project ID 仍为 403/404。
3. 未登录与缺 CSRF 的原拒绝合同继续有效；不得用关闭注册/所有登录接口换取测试通过。
4. 检查会话行数/Owner 与真实 HTTP 行为，不能仅断言错误字符串。

**停止条件：** 跨用户签发/撤销及正常认证合同都通过后结束，不在此批加入团队成员管理、密码重置平台或 SSO。

## 5. OPT-02：收拢实例公共配置权限

**目标：** 用户控制自己的项目，实例维护者控制影响所有用户的公共配置。

**先读：** `server.go:233–255`；`configuration.go:57–104,139–185,217–233`；`provider_registry.go:87–215`；`password_auth.go:78–155`；当前 Vault 首用流程及 `GetOrganizationRole` 实现。

**允许改动：** `Src/internal/application/{security,configuration,provider_registry}.go`、HTTP 相关 Handler、必要的实例维护者初始化/恢复入口、对应设置 UI 和测试；不得顺带建设完整用户管理后台。

**产品决策：** 沿用已存在的实例公共 Provider/Vault；普通用户可选用已开放的模型、修改自己的偏好，不能修改公共端点/凭据、删除 Provider、修改治理规则或轮转公共 Vault。共享模型的费用归属先沿用现有用量记录，不新增计费系统。

**实施要求：**

- Profile 仅选择装配方式，不能意味着 `Administrator=true`。使用现有组织 owner 身份与明确可信的维护入口。
- 给全部公共写操作加统一用例授权，包含 Provider 创建/更新/删除及模型目录中会改变共享配置的操作；修复 requireOwner 不能遗漏不调用它的入口。
- 公共读操作只返回完成选择/诊断所需的非敏感信息。不要给管理员默认读取其他用户私有项目的能力。
- 处理首用与升级：新安装若让首个账户成为维护者，必须在受控初始化状态中事务性认领且只能一次；不能长期将“注册成功”映射成管理员。旧数据库不能猜测哪个普通用户应被提升；提供由本机部署者针对确切账号完成的维护者恢复路径，先用隔离旧库验证。
- 保持 UI 状态与后端能力一致。普通用户缺少可用公共模型时给明确说明；不要在用户打开设置时弹出一连串无权执行的按钮。

**必须验收：** 普通 A/B 修改公共 Provider、治理、Vault 被拒绝且数据未变；维护者可正常配置；A/B 能使用允许的模型并独立保存个人偏好；新安装一次初始化和旧实例维护者恢复均不锁死产品。测试不得把所有账户设成管理员。

**安全承诺：** 文档明确当前宿主受控执行的边界。若部署目标是互不信任用户共用任意 Shell/STDIO 执行宿主，本批不能把应用级隔离宣称为强隔离，应另立进程隔离决策；不自动扩展当前代码范围。

**停止条件：** 公共写边界与维护者可达性闭环后结束，不扩展团队角色矩阵，也不迁移成每用户一套 Vault。

## 6. OPT-03：认证边界管理前端缓存与流

**目标：** A 会话过期后在同浏览器登录 B，从第一帧起只显示 B 的数据。

**先读：** `Src/web/src/main.tsx`、`app/authenticated-root.tsx`、`app/shell.tsx`、`features/runs/run-events-provider.tsx`、`shared/api/client.ts` 及身份相关查询。

**允许改动：** 认证边界、请求取消与 SSE 生命周期、必要的用户工作台重挂载和相关测试。优先集中处理，不给每个组件散加相同 effect，不全面改写 query key。

**实施要求：**

- 建立小型明确的“认证失效/身份切换”处理流程：停止旧订阅与在途请求、清空私有查询状态、重新获取 bootstrap 后挂载用户工作台。
- 不能仅 `invalidateQueries` 后继续显示旧数据；取消失败或无法取消的旧请求也不得回填新用户会话，可用身份代次/生命周期校验解决。
- 保留已有按 user ID 命名的 Composer 草稿；不得误删其他软件存储或把所有 localStorage 清空。用户隐私数据与无敏感性的外观偏好区别处理。
- 已离开的用户的服务端任务继续遵守持久运行合同；清浏览器状态不等于取消其后台任务。

**必须验收：** A 数据装载后令会话失效，再登录 B；分别延迟旧项目响应、偏好响应和 SSE 正文。DOM 与新缓存都不得出现 A 的哨兵内容；显式退出再登录、登录同一用户、两个独立浏览器账号并行仍正常。允许将认证成功后的完整页面重载作为最小实现，但须验证旧内容不闪回、旧流不复用及正常登录体验。

**停止条件：** 身份切换链路闭环即结束，不迁移前端状态库、不重做路由。

## 7. OPT-04：一次发送可恢复且不重复

**目标：** 失败不丢目标和附件，重试不重复创建任务。

**先读：** `project-page.tsx:906–979,1043–1079,253–265`；`client.ts:980–1058,1234–1235`；服务端 ProjectTurn 幂等、持久消息和会话队列实现。

**允许改动：** Composer 发送控制器/小组件、传输函数及必要的 ProjectTurn 幂等契约、相邻单测和 E2E。允许将发送逻辑从大页面提取，不顺带拆整个项目页面。

**实施要求：**

- 每次发送冻结文本、附件 Asset ID、Skill、模式/队列语义和请求 Key；重试该发送复用同一 Key，新编辑内容是新发送。
- 明确四种状态：发送中、已接收、明确失败、确认不明。服务端已持久接收但断流时，先查询/复用幂等结果，不直接另建任务。
- 输入框可以立即用于下一条输入，但失败卡必须保留原内容和附件并可恢复；旧失败不能覆盖后来输入。
- 复用附件记录，不再次上传同一文件；账号切换遵守 OPT-03，不能恢复上一用户的失败消息。
- 若现有幂等接口不能查询/恢复结果，补最窄的合同；不可通过时间窗口/相似文本猜测两条请求相同。

**必须验收：**

1. 请求尚未到服务器即失败：内容与附件可恢复；用户新草稿不被覆盖。
2. 服务端提交后客户端未收到响应/流中断：重试同一发送只对应一个持久用户消息及一个预期 Task/队列项；Ask 路径不得凭空增加 Task。
3. 连点、重新发送、后继消息和 Steering/Follow-up 均遵守原语义；真正的新请求不被误去重。
4. 动态测试服务注入故障；同时检查数据库结果与 UI，不能只做静态截图或测组件内部 state。

**停止条件：** 上述有限失败集合通过后结束；不扩展为离线同步系统或通用消息中间件。

## 8. OPT-05：同项目会话独立并发

2026-09-08 产品决策取代原项目级整轮排队。详细设计与验收见 [会话并发与任务恢复设计](Oktapod_会话并发与任务恢复设计_V1.0.md)。

- Conversation 是消息有序与任务准入边界；不同会话可同时执行，一方审批/暂停不阻塞其他会话。
- 创建、同步/后台领取、恢复和 Worker 选步均按会话约束；迁移 070 将 claimed 唯一索引收窄到会话，保留幂等、FIFO 与 claim_version。
- 共享目录采用单次写文件/命令/Git 操作互斥及编辑原文 Hash 冲突检查，不将模型轮次或等待审批纳入工作区锁。
- 同会话未结束执行租约和未知副作用仍阻止危险重放；外部编辑器不在进程内互斥的保护范围。
- Git 差异反映共享工作区，不宣称当前任务独占；Artifact 与工具收据按 Run 归属。自动 worktree/Handoff 仍不进入本批范围。

**必须验收：** 同项目不同会话实际并发、同会话 FIFO、审批隔离、重复领取/过期 starter 拒绝、重启续接、编辑冲突及真实任务恢复。

## 9. OPT-06/07：有条件的工程收口

### OPT-06 随改动处理，不单独全面重构

- API 变更同步 `Src/api/openapi.yaml` 与 Go 生成物；同时核对 TypeScript 对应类型和真实 HTTP 响应。必要时生成或校验“这批涉及的类型”，保留现有统一请求层，不一次替换全客户端。
- 业务规则从 Store 提取时采用纯输入/输出函数，旧事务继续原子提交；只有本批会修改且能降低测试耦合的规则才提取。
- 相关 README/设计文档/验收矩阵同步，消除 HTML 预览、文档 Runtime 发布范围等与本批相关的冲突。README 保持 60 行内，正文不再无限叠加补丁段落。
- 需要新增 agentloop/harness 等目录说明时，在项目目录规范中补实际职责，不追加临时任务记录到全局规则。

完成判断是“修改的行为有合同与证据”，不是“全部大文件拆完”。

### OPT-07 仅准备发行时启动

- 输入：自包含 Runtime stage、包内依赖与许可证、签名 Key 文件和 Key ID、信任键，以及 Windows/Linux 构建环境；沿用现有脚本定义。
- 补齐 CI 输入来源与准备步骤。隔离烟测可以使用测试专用签名材料，但必须明确测试信任链，不能把测试包冒充正式发布包，也不能暴露正式私钥给不受信 PR。
- 执行项目已有 `pnpm release:build`、`pnpm release:smoke`，验证真实工件、签名、Hash、运行时加载及资源可用性；Windows/Linux 分别记录证据。
- 缺输入时记录 `BLOCKED_ENV`，不改脚本跳过检查、不仅创建目录记录伪装成功、不自动恢复旧 `RC_READY`。普通 verify/race 结果单独报告。

## 10. 每批统一验收与交接

### 10.1 执行前

1. 读取项目 `AGENTS.md`、本方案、配套评审、相关代码及当前验收矩阵；记录实际 HEAD 与工作树变更，保留他人未提交修改。
2. 按代码重新验证本批发现。如果已经修复，补上证据并跳过重复实现；不能仅凭文件名或历史文档继续旧重构计划。
3. 明确本批允许文件、回归场景和不涉及的模块。外部环境不足不妨碍独立的代码与测试工作，只有依赖该环境的验收标记阻塞。

### 10.2 代码改动后的门禁

先运行本批定向回归；通过后运行项目现有完整开发门禁：

```powershell
$env:GOCACHE="$env:TEMP\go-build-cache"
pnpm verify
```

前端/用户主路径改动，再运行：

```powershell
pnpm test:e2e
```

身份改动补跑现有账号 E2E（并将新增场景纳入被实际运行的套件）：

```powershell
pnpm --dir Src/web test:e2e:auth
```

并发/恢复改动由支持 race 的 Ubuntu 环境执行 `pnpm test:race`；当前 Windows 无法运行时明确未验证，不能声称双平台通过。纯文档改动只检查链接、路径、编号、范围和 diff，无须触发模型、构建或数据写入测试。

首次多用户修复至少验证评审 §6 的身份入口、私有资源和前端切号矩阵。受控文件/下载/预览/SSE 各选已有代表路径补负向 HTTP 测试；已有有效测试可复用，不为每个函数新增镜像测试。

### 10.3 完成记录

每批在现有验收矩阵证据日志追加一行，记录任务 ID、实际代码基线、变更、定向/全量测试、未关闭项。不要把本方案变成第二张完成度矩阵。

交接记录最少包含：

| 字段 | 必填内容 |
|---|---|
| 任务 | OPT 编号与本批用户行为变化 |
| 证据 | 代码路径、测试名、实际执行命令与结果 |
| 状态 | PASS / PARTIAL / BLOCKED_ENV；阻塞时写清缺少什么 |
| 兼容 | 旧会话/Run/数据库/私有项目是否保持；如有迁移写升级验证 |
| 后续 | 下一任务、已排除的重复工作和剩余风险 |

某项测试通过后不反复重跑，除非又改了相关代码或仍有未解问题。不能以“编译成功”替代用户闭环，也不能以“文档完成”替代发布成功。
